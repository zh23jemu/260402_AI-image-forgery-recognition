# 当前判断

- 论文主线应坚持“复现 + 分析 + 联合验证”，不要把工作讲成纯复现，也不要把联合训练讲成已经获得大幅性能提升。
- FSD 仍应作为主干泛化检测模型来表述；Stay-Positive 更适合固定真假对照任务；LVLM 目前更适合作为结构化语义分析与轻量监督来源。
- 联合训练分两层来讲最稳妥：
- 第一阶段：FSD + Stay-Positive 思路接入，但实际日志显示 `valid_sp_samples=0`，因此这一阶段更接近训练链路预留与方案验证，不能夸大其量化贡献。
- 第二阶段：FSD + LVLM 轻量辅助头真正进入训练图，日志中 `valid_lvlm_samples` 为非零，且可输出 `lvlm_f1`，说明语义监督已经被量化接入。
- 第二阶段闭集结果中，ADM 从 5000 step 到 10000 step 呈现提升，最终指标为 Accuracy 0.952222、AP 0.974539、LVLM F1 0.177778；SD 与 Midjourney 也恢复到与联合基线相近水平。
- 与用户/导师沟通时，建议将联合训练结论表述为：完成了多模型信息进入统一训练流程的验证，其中 LVLM 语义监督已实现可训练、可量化、可汇总。
- 当前已经通过 RecallLoom 固化上述口径，后续恢复项目应优先沿用，避免论文、答辩和代码说明出现不一致。

# 风险与未决问题

- 论文与答辩阶段最大的风险不是代码链路，而是表述风险：如果把联合训练写得过强，容易被导师追问“为何主任务提升不显著”。
- LVLM 标注规模仍然较小，当前更适合作为补充实验与方法可行性支撑，不适合写成大规模成熟语义监督体系。
- 用户后续仍可能继续修改最终论文 `docx` 排版或文字，因此所有答辩口径需要与最终论文版本保持一致。
- 服务器训练已基本完成，但如后续还要追加实验，应先判断是否真的影响最终论文，不要在答辩前引入新的不稳定变量。
